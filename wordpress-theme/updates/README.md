# بروزرسانی قالب با پچ — ساختار استاندارد

این پوشه «کاتالوگ بروزرسانی» قالب آمل نوین است و در تب **تنظیمات قالب → بروزرسانی قالب** خوانده می‌شود.
منطق سمت وردپرس در `amolnovin/app/Updater/Patcher.php` است.

```
wordpress-theme/
├── updates/
│   ├── manifest.json              ← کاتالوگ نسخه‌ها (این فایل به سایت‌ها fetch می‌شود)
│   ├── manifest.schema.json       ← JSON Schema کاتالوگ
│   ├── patches/
│   │   └── amolnovin-1.0.0-to-1.1.0.zip
│   └── README.md
└── amolnovin/                     ← خود قالب (نسخه در style.css)
```

## اصول

| اصل | توضیح |
|---|---|
| فقط تغییرات | پچ فقط فایل‌های تغییرکرده را دارد؛ آپلود کل قالب لازم نیست. |
| امضا | `sha256` بسته + `sha256` هر فایل؛ هر ناهم‌خوانی باعث توقف کامل اعمال می‌شود. |
| مسیر امن | مسیرها نسبت به ریشه‌ی قالب و بدون `..`/مسیر مطلق؛ در غیر این صورت رد می‌شود. |
| https | بسته فقط از میزبان‌های مجاز و با https دانلود می‌شود (`amol/updater/allowed_hosts`). |
| پشتیبان | پیش از هر نوشتن، فایل‌های موجود در `wp-content/uploads/amolnovin-backups/<version>-<date>/` کپی می‌شوند. |
| بازگردانی | هر پچ اعمال‌شده یک دکمه‌ی «بازگردانی» دارد (فایل‌های پچ حذف/بازگردانی می‌شوند). |
| تاریخچه | هر بررسی/اعمال/بازگردانی در جدول `wp_options → amol_update_state` ثبت می‌شود. |
| سایت بدون اینترنت | بسته‌ی ZIP را می‌توان از تب بروزرسانی بارگذاری کرد؛ همان اعتبارسنجی‌ها اجرا می‌شود. |

## قالب ورودی کاتالوگ

```jsonc
{
  "schema": 1,
  "theme": "amolnovin",
  "name": "قالب وردپرس آمل نوین",
  "generated": "2026-10-31T00:00:00Z",
  "releases": [
    {
      "version": "1.1.0",
      "date": "2026-10-31",
      "channel": "stable",
      "requires": { "php": "8.3", "wp": "6.6", "from": ["1.0.0"] },
      "package": "patches/amolnovin-1.0.0-to-1.1.0.zip",
      "sha256": "…۶۴ کاراکتر هگز…",
      "notes": "پنل تنظیمات، هماهنگی افزونه‌ها، بروزرسانی با پچ",
      "files": [
        { "path": "style.css", "sha256": "…" },
        { "path": "app/Admin/Settings.php", "sha256": "…" }
      ],
      "deleted": []
    }
  ]
}
```

`package` می‌تواند مسیر نسبی به محل `manifest.json` باشد (همان‌طور که در مخزن است) یا آدرس کامل https
(مثلاً asset یک GitHub Release). `requires.from` تعیین می‌کند پچ روی کدام نسخه‌ها قابل اعمال است.

## ساخت بسته

از ریشه‌ی مخزن:

```bash
cd wordpress-theme
./scripts/make-patch.sh v1.0.0 v1.1.0 1.1.0 "پنل تنظیمات قالب و هماهنگی افزونه‌ها"
```

اسکریپت:

1. فایل‌های تغییرکرده/حذف‌شده را از `git diff` استخراج می‌کند،
2. آن‌ها را در `updates/patches/amolnovin-<from>-to-<version>.zip` می‌ریزد،
3. برای هر فایل `sha256` می‌سازد و `manifest.json` را (هم داخل ZIP برای نصب آفلاین و هم در کاتالوگ) به‌روز می‌کند.

پوشه‌های `updates/`، `public/build/`، `vendor/`، `node_modules/` و فایل‌های موقت از بسته حذف می‌شوند
(کاتالوگ نباید خودش را بازنویسی کند).

## انتشار

1. نسخه‌ی `style.css` و `package.json` را بالا ببرید.
2. `make-patch.sh` را اجرا کنید و `updates/manifest.json` + فایل ZIP را کامیت کنید.
3. تگ بسازید و Release را با همان ZIP منتشر کنید.

سایت‌ها در بازه‌ی حداکثر ۱۲ ساعت (یا با دکمه‌ی «بررسی بروزرسانی») نسخه‌ی جدید را می‌بینند.
