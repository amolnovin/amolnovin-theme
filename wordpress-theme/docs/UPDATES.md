# بروزرسانی قالب با پچ

قالب آمل نوین خودش را از طریق **پچ** بروزرسانی می‌کند: بدون آپلود کل قالب، بدون از دست‌دادن سفارشی‌سازی‌ها و با
امکان بازگردانی. همه‌چیز از **پیشخوان ← آمل نوین ← بروزرسانی قالب** انجام می‌شود؛ ساختار فایل‌ها در
[`../updates/README.md`](../updates/README.md) توضیح داده شده است.

## ۱. آنچه سایت انجام می‌دهد

| مرحله | رفتار |
|---|---|
| بررسی | هر ۱۲ ساعت (و با دکمه‌ی «بررسی بروزرسانی») فایل `manifest.json` از آدرس تنظیم‌شده خوانده می‌شود. |
| انتخاب | فقط نسخه‌هایی که از نسخه‌ی فعلی شما ساخته شده‌اند (`requires.from`) پیشنهاد می‌شوند. |
| دانلود | فقط از https و میزبان‌های مجاز؛ نتیجه در حافظه‌ی موقت ذخیره می‌شود. |
| اعتبارسنجی | `sha256` بسته و `sha256` هر فایل با کاتالوگ مقایسه می‌شود؛ مسیرهای ناامن (`..`، مسیر مطلق) رد می‌شوند. |
| پشتیبان | فایل‌های فعلی در `wp-content/uploads/amolnovin-backups/<version>-<timestamp>/` کپی می‌شوند. |
| نوشتن | فایل‌های پچ جای‌گذاری و فایل‌های `deleted` حذف می‌شوند؛ کش opcache فایل‌های PHP پاک می‌شود. |
| ثبت | نسخه، زمان، تعداد فایل و مسیر پشتیبان در گزینه‌ی `amol_update_state` ذخیره می‌شود. |
| بازگردانی | هر ردیف در «پچ‌های اعمال‌شده» دکمه‌ی بازگردانی دارد. |

## ۲. تنظیمات

| فیلد | پیش‌فرض | توضیح |
|---|---|---|
| آدرس فهرست بروزرسانی | `https://raw.githubusercontent.com/amolnovin/amolnovin-theme/main/wordpress-theme/updates/manifest.json` | می‌توانید آن را روی سرور خودتان هم بگذارید. |
| کانال | پایدار | برای انتشار آزمایشی از `channel: beta` در کاتالوگ و کانال «آزمایشی» استفاده کنید. |
| بررسی خودکار | روشن | فقط برای کاربرانی که `update_themes` دارند و حداکثر هر ۱۲ ساعت. |

فیلترها برای توسعه‌دهندگان:

```php
add_filter('amol/updater/manifest_url', fn () => 'https://cdn.example.com/amolnovin/manifest.json');
add_filter('amol/updater/allowed_hosts', function ($hosts) { $hosts[] = 'cdn.example.com'; return $hosts; });
```

## ۳. انتشار یک نسخه‌ی جدید

```bash
cd wordpress-theme

# ۱) نسخه را در style.css و package.json بالا ببرید (مثلاً 1.1.1) و CHANGELOG را بنویسید
# ۲) کامیت کنید
git add -A && git commit -m "release 1.1.1" && git push

# ۳) پچ از آخرین نسخه بسازید و کاتالوگ را به‌روز کنید
#    اگر نسخه CSS/JS را عوض کرده، آرگومان ششم (build-ref) را هم بدهید تا فایل‌های build هم داخل پچ بروند:
./scripts/make-patch.sh v1.1.0 HEAD 1.1.1 "رفع باگ‌ها و بهبودها" 1.1.0 v1.1.0
git add updates && git commit -m "patch 1.1.1" && git push

# ۴) تگ بسازید؛ GitHub Actions (.github/workflows/release.yml) خودش
#    composer/npm را نصب می‌کند، zip کامل را می‌سازد و به Release می‌چسباند.
git tag v1.1.1 && git push origin v1.1.1
```

بعد از ساخت Release، بسته‌ی پچ باید به همان Release هم بچسبد (تا دکمه‌ی «بروزرسانی» در پیشخوان کار کند).
ورک‌فلوی `release.yml` این کار را خودکار انجام می‌دهد: هر فایل `updates/patches/amolnovin-*-to-<version>.zip`
را پیدا می‌کند و به ریلیز اضافه می‌کند. برای نسخه‌های قدیمی‌تر یا آپلود دستی:

```bash
gh release upload v1.1.1 updates/patches/amolnovin-1.1.0-to-1.1.1.zip --clobber
```

> اگر Actions در ریپو غیرفعال است، zip کامل را با `./scripts/build-zip.sh` (روی ماشینی با PHP 8.4 و Node 20)
> بسازید و دستی به Release آپلود کنید.

> پچ‌ها تجمعی نیستند: هر پچ از **یک** نسخه‌ی پایه ساخته می‌شود. اگر چند نسخه عقب هستید، پچ‌ها را به ترتیب
> اعمال کنید (کاتالوگ ترتیب را نشان می‌دهد). برای پرش چندنسخه‌ای، از یک zip کامل نصب دوباره استفاده کنید.

## ۴. سایت بدون دسترسی به اینترنت

بسته‌ی ZIP را از GitHub Release دانلود کنید و در همان تب، بخش «اعمال پچ آپلودی» بارگذاری کنید. بسته در ریشه‌ی
خود `manifest.json` دارد (اسکریپت آن را می‌سازد) و همان اعتبارسنجی مسیر/امضا اجرا می‌شود.

## ۵. بازیابی اضطراری

اگر بعد از بروزرسانی سایت مشکل داشت:

1. **پیشخوان ← آمل نوین ← بروزرسانی قالب ← پچ‌های اعمال‌شده ← بازگردانی**، یا
2. فایل‌های پوشه‌ی پشتیبان را با FTP روی قالب کپی کنید، یا
3. از نسخه‌ی کامل zip همان نسخه‌ی قبلی استفاده کنید.

پوشه‌ی پشتیبان با `.htaccess` و `index.php` محافظت می‌شود و از بیرون قابل دانلود نیست؛ پس از اطمینان از
سلامت سایت می‌توانید آن را پاک کنید.

## ۶. امنیت

- اعمال پچ فقط با قابلیت `update_themes`/`manage_options` و nonce انجام می‌شود.
- کد اجرایی از بسته اجرا نمی‌شود؛ فقط فایل‌ها کپی/حذف می‌شوند.
- بسته بدون `sha256` یا با فهرست فایل ناقص اعمال نمی‌شود (fail-closed).
- منبع باید https و در فهرست میزبان‌های مجاز باشد؛ در غیر این صورت خطای «میزبان مجاز نیست».

## ۷. نیازمندی‌ها

- وردپرس ۶.۶+ و **PHP 8.4+**؛ فایل `composer.lock` قالب، نسخه‌های Symfony 8 را قفل کرده است که حداقل PHP 8.4.1
  می‌خواهند. اگر سایت روی PHP 8.3 است، پیش از نصب نسخه‌ی PHP را ارتقا دهید یا وابستگی‌ها را با
  `composer update` روی همان نسخه بازتولید کنید.
