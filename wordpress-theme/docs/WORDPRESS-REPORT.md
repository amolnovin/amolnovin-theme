# گزارش تبدیل قالب HTML «آمل نوین» به قالب وردپرس (Sage 11)

> نتیجه‌ی یک خط: همه‌ی ۵۸ صفحه‌ی قالب HTML در وردپرس با همان HTML، CSS و جاوااسکریپت ساخته می‌شود و **۱۱۴ از ۱۱۴ اسکرین‌شات تمام‌صفحه پیکسل‌به‌پیکسل با قالب HTML یکسان است**؛ محتوا و تنظیمات حالا از پیشخوان وردپرس مدیریت می‌شود.

## ۱. بررسی قالب HTML (`amolnovin-theme`)

### ابعاد
| مورد | مقدار |
|---|---|
| صفحه‌ها | ۵۸ (۵۷ صفحه‌ی ایندکس‌شدنی + ۴۰۴): صفحه‌ی اصلی، ۱۵ صفحه‌ی خدمات/اطلاعاتی، ۲۰ نوع سایت، پورتفولیو + ۱۲ مطالعه‌ی موردی، فروشگاه افزونه، وبلاگ + ۵ مقاله، نقشه‌ی سایت |
| قالب‌های Jinja | ۱۲ فایل قالب (شامل `base` و `macros`) و ۴ partial، در مجموع حدود ۱٬۳۱۵ خط؛ `macros.html` شامل ۱۲ ماکرو (`sec_head`، `faq`، `lead_form`، `cta_band`، `project_card` ...) |
| رندرکننده‌ی بخش‌ها | ۲۷ نوع بخش در `render_section` (۲۱ نوع در صفحه‌های فعلی استفاده شده است) |
| داده‌ها | حدود ۳۹۰ کیلوبایت پایتون (داده و منطق ساخت): صفحه‌ها، ۲۰ نوع سایت، ۲۰ نمونه‌کار، ۱۴ افزونه، ۵ مقاله؛ خروجی JSON آن‌ها حدود ۶۶۰ کیلوبایت |
| CSS | ۵ فایل، حدود ۱۰۰ کیلوبایت خام (پس از ساخت: ۸۸٫۸ کیلوبایت، **۱۸ کیلوبایت gzip**) |
| JS | `main.js` بدون وابستگی، ۲۲ کیلوبایت خام (پس از ساخت: ۱۵ کیلوبایت، **۶ کیلوبایت gzip**) |
| تصویر و فونت | ۱۵۲ تصویر (۶٫۵ مگابایت: وب‌پی، SVG، ماکاپ ۲۰ نوع سایت) و فونت وزیرمتن |

### رفتارهای تعاملی (`main.js`)
تم روشن/تیره، ابرمنوهای هدر، منوی موبایل، جست‌وجوی Ctrl+K، فیلتر و جست‌وجوی نمونه‌کارها/افزونه‌ها/مقالات، ماشین‌حساب هزینه، «پیشنهاد هوشمند» نوع سایت، فرم مشاوره با بازگشت به واتساپ، فهرست مطالب مقاله، لایت‌باکس، نقشه‌ی تنبل، شمارنده‌ها، متن چرخان.

### خط‌لوله‌ی ساخت (آنچه باید در PHP بازتولید می‌شد)
Jinja ← sprite آیکن فقط برای نمادهای همان صفحه ← تبدیل ارقام به فارسی در متن‌ها و بعضی صفت‌ها ← گراف JSON-LD (`schema.py`) ← `sitemap.xml`، `robots.txt`، `llms.txt`، `manifest`، `feed.xml`، ایندکس جست‌وجو ← `.htaccess` (ریدایرکت‌ها، هدرها).

### یافته‌های بازبینی (ایرادهای موجود در خود قالب HTML)
| # | یافته | وضعیت در قالب وردپرس |
|---|---|---|
| ۱ | بین ۱۰۲۱ تا ۱۲۰۳ پیکسل (iPad افقی، لپ‌تاپ‌های کوچک) هدر کامل از صفحه بیرون می‌زند: دکمه‌ی «مشاوره‌ی رایگان» بریده و اسکرول افقی ایجاد می‌شود | **اصلاح شد** (منوی همبرگری تا ۱۲۳۵px؛ قابل خاموش‌کردن در سفارشی‌سازی) |
| ۲ | `id="content"` در `/services/seo/` دوبار وجود دارد (`<main>` و یک بخش)؛ لینک «تولید محتوا» در منوی میان‌صفحه به بالای صفحه می‌پرید | **اصلاح شد** (`section-content`) |
| ۳ | قیمت‌ها، شماره، ایمیل و نشانی داخل ده‌ها متن «پخته» شده بودند | **توکن‌بندی شد** (`[[price_design]]`، `[[phone_display]]` ...) تا با Customizer هماهنگ بمانند |
| ۴ | لینک «ماشین‌حساب هزینه» داخل پاراگراف فقط با رنگ متمایز است (یک امتیاز دسترس‌پذیری) | بدون تغییر ماند (طراحی اصلی)؛ راه‌حل در بخش ۷ |
| ۵ | فرم‌ها به `api/lead.php` می‌روند (فایل PHP مستقل) | با REST وردپرس و ذخیره در پیشخوان جایگزین شد |
| ۶ | قالب فقط با آدرس نسبی و روی `file://` تست شده بود | در وردپرس آدرس‌ها مطلق و بر پایه‌ی `home_url` است |

## ۲. معماری قالب وردپرس

### چرا این معماری؟
- **Sage 11 بدون Tailwind:** طراحی پروژه یک سیستم CSS دست‌نویس است؛ بازنویسی آن به Tailwind، «بدون کوچک‌ترین تغییر» را غیرممکن می‌کرد. پس همان ۵ فایل CSS و `main.js` به Vite داده شده و فقط مسیر فایل‌ها (`../img/` ← `@images/`) عوض شده است.
- **Blade به‌جای Jinja:** هر ماکرو یک کامپوننت (`<x-faq>`)، هر نوع بخش یک partial، هر قالب صفحه یک ویوی وردپرس. ساختار قالب‌ها عمداً به نسخه‌ی Jinja نزدیک نگه داشته شده تا مقایسه‌ی ۱ به ۱ ممکن باشد.
- **محتوا در پایگاه داده، نه فایل:** صفحه‌ها = `page`، نوع‌های سایت = `website_type`، نمونه‌کارها = `project`، افزونه‌ها = `wplm_product`، مقاله‌ها = `post` (هر کدام با ویرایشگر خود وردپرس). محتوای ساختاری (Hero، بخش‌ها، FAQ ...) در متای JSON ذخیره و با ویرایشگر ساختاری قالب ویرایش می‌شود.
- **بدون وابستگی به افزونه‌ی پولی:** ACF Pro یا Page Builder لازم نیست؛ ویرایشگر ساختاری (۱۰ کیلوبایت JS) برای هر ساختار JSON فرم می‌سازد.
- **خروجی‌گیر مرکزی:** همان دو مرحله‌ی پایانی `build.py` (sprite آیکن و ارقام فارسی) در یک `ob_start` پیش از ارسال صفحه اجرا می‌شود؛ پس خروجی ارقام و آیکن‌ها با نسخه‌ی HTML یکی است.

### جریان داده
```
قالب HTML (پایتون) ──export_wp.py──▶ resources/data/*.json ──Importer──▶ پایگاه داده‌ی وردپرس
                                                                        │
                    Repo / PageData / Site (آرایه‌هایی با همان شکل دیکشنری‌های Jinja) ◀─┘
                                                                        │
                             Blade (layouts · sections · components · page-sections) ──▶ HTML
                                                                        │
                                   Html::finalize()  (توکن‌ها · sprite آیکن · ارقام فارسی)
```

### مدل محتوا
| نوع | آدرس | داده‌ی ساختاری |
|---|---|---|
| `page` | `/…/` (۲۰ صفحه؛ زیرصفحه‌های `/services/*`) | `_amol_page`: Hero، بخش‌ها، FAQ، crumbs، Schema |
| `website_type` | `/services/web-design/{slug}/` | `_amol_entity` (امکانات، ساختار، سئو، FAQ ...) + `_amol_page` |
| `project` | `/projects/{slug}/` (۱۲ مطالعه‌ی موردی + ۸ کارت) | `_amol_entity` + `_amol_page` |
| `wplm_product` | فقط پیشخوان و صفحه‌ی فروشگاه | `_amol_entity` |
| `post` | `/{slug}/` | بدنه = بلوک HTML؛ `_amol_entity` (FAQ، مرتبط‌ها) |
| `amol_lead` | فقط پیشخوان | درخواست‌های فرم |
| سئو (همه‌ی نوع‌ها) | — | `_amol_seo_title`، `_amol_seo_desc`، `_amol_h1`، `_amol_kw`، `_amol_noindex` |

## ۴. نحوه‌ی تأیید «بدون کوچک‌ترین تغییر»

برای هر صفحه خروجی قالب HTML و قالب وردپرس هم‌زمان گرفته و با ابزارهای زیر مقایسه شد (ابزارها در `qa-tools/` هستند).

| ابزار | چه چیزی را می‌سنجد | نتیجه |
|---|---|---|
| `wp_compare.py` | درخت DOM بدنه (تگ، صفت‌های نرمال‌شده، متن)، تگ‌های `<head>` (عنوان، توضیح، canonical، OG، آیکن‌ها) و **کل JSON-LD** | **۵۸ از ۵۸ صفحه یکسان** |
| `wp_visual.py` | اسکرین‌شات تمام‌صفحه، دسکتاپ ۱۴۴۰ و موبایل ۳۹۰، سنجش پیکسلی | **۱۱۴ از ۱۱۴ یکسان**؛ با تلورانس صفر نیز ۱۲ از ۱۲ (روشن و تیره) |
| `qa_js.py` | رفتار JS: منوها، جست‌وجو، فیلترها، ماشین‌حساب، فرم، تم، موبایل | **۱۹ از ۱۹** و بدون خطای کنسول |
| `wp_qa.py` | sitemap، robots، llms.txt (کاملاً یکسان)، manifest، RSS، ایندکس جست‌وجو، ۸ ریدایرکت، ۴۰۴، هدرهای امنیتی، توکن‌ها با Customizer، لاگ PHP | **۲۷ از ۲۷** |
| `menu_check.py` | دراپ‌داون «بیشتر» زیر دکمه‌ی خودش، `header__actions` سمت چپ در موبایل، کیبورد و لمس | **همه پاس** |
| `overflow.py` | اسکرول افقی همه‌ی ۵۸ صفحه | **۰** در ۳۶۰، ۳۹۰، ۷۶۸، ۱۰۲۱، ۱۰۲۴، ۱۱۰۰، ۱۲۰۰، ۱۲۳۵، ۱۲۳۶، ۱۲۸۰ و ۱۴۴۰ px |
| `wp_admin_test.py` | ورود به پیشخوان، ویرایشگر ساختاری، ذخیره با ویرایشگر بلوک، افزودن بخش، نمایش در سایت | **۱۱ از ۱۱** |
| html5lib | خطای تجزیه‌ی HTML و `id` تکراری | **۰ در ۵۸ صفحه** |
| Lighthouse (موبایل) | عملکرد / دسترس‌پذیری / بهترین‌روش‌ها / سئو | **۸۹–۹۴ / ۹۷–۱۰۰ / ۱۰۰ / ۱۰۰** (برابر یا بهتر از قالب HTML) |

### آزمون نصب تمیز
یک وردپرس ۷٫۱٫۳ کاملاً تازه با دیتابیس جدا ساخته شد، **فقط** `amolnovin-sage-theme.zip` از طریق `wp theme install` نصب و فعال و سپس `wp amol import --reset` اجرا شد (همان کاری که کاربر انجام می‌دهد). همه‌ی آزمون‌ها روی آن اجرا شد:
DOM ‏**۵۸/۵۸**، وردپرس ‏**۲۷/۲۷**، رفتار JS ‏**۱۹/۱۹**، هدر و ریسپانسیو **همه پاس**، پیشخوان ‏**۱۱/۱۱**، سرریز افقی **۰** در ۳۹۰ و ۱۰۲۴ و ۱۴۴۰px روی ۵۸ صفحه، و **۱۶/۱۶ مقایسه‌ی پیکسلی در حالت تیره با تلورانس صفر**.
این آزمون ثابت می‌کند بسته‌ی production خودکفاست (`vendor` و `public/build` داخل zip است) و ساخت از صفر (`composer install --no-dev` + `npm ci` + `npm run build`) تکرارپذیر است.

**آزمون حساسیت (mutation):** یک کلمه از متن یک صفحه در پایگاه داده تغییر داده شد؛ `wp_compare.py` فوراً تفاوت را گزارش کرد، سپس با اجرای دوباره‌ی واردکننده همان صفحه دوباره یکسان شد.

### نرمال‌سازی‌های مقایسه (هیچ‌کدام برای بیننده دیدنی نیست)
آدرس نسبی در برابر مطلق، هش فایل‌های Vite، ترتیب کلاس‌ها، قالب‌بندی اعداد در `style` (`0.0s` / `0s`)، JSON داخل `data-*` (ترتیب کلید و escape)، ترتیب نمادهای sprite، کلاس‌های `body_class()` وردپرس، نام میزبان (`localhost` در برابر `amolnovin.ir`) و رمزگذاری لینک‌های اشتراک‌گذاری.

## ۵. تفاوت‌های آگاهانه با قالب HTML
۱. **منوی همبرگری ۱۰۲۱–۱۲۳۵px** (ایراد شماره‌ی ۱ بالا) — ۹ خط در `06-wp.css`، قابل خاموش‌کردن.
۲. **شناسه‌ی `section-content`** در `/services/seo/` (ایراد شماره‌ی ۲).
۳. **فرم‌ها** به REST وردپرس می‌روند؛ `/feed.xml` ریدایرکت ۳۰۱ به `/feed/` است.
۴. تاریخ مقاله‌ها و سال ©، اگر تاریخ جاری تغییر کند، خودکار به‌روز می‌شود (سال شمسی فوتر پویاست).

## ۶. محدودیت‌ها و پیشنهاد گام بعد
- متن «کپی» صفحه‌ی اصلی و ۱۵ صفحه‌ی خدمات مثل قالب HTML ثابت است. صفحه‌ی اصلی در `front-page.blade.php` و صفحه‌های داخلی در ویرایشگر ساختاری ویرایش می‌شوند؛ تبدیل بخش‌های صفحه‌ی اصلی به داده‌ی قابل‌ویرایش ممکن اما خارج از «بدون تغییر» بود.
- ویرایشگر ساختاری یک فرم عمومی است؛ اگر بخواهید می‌توان هر نوع بخش را به یک **بلوک Gutenberg** سفارشی تبدیل کرد (ویرایش درجا).
- محتوای نمونه (ماشین‌حساب، سرفصل‌های دوره، توضیح افزونه‌ها، مقاله‌ها) همان متن قالب HTML است و باید با اطلاعات واقعی جایگزین شود (در گزارش قبلی علامت‌گذاری شده بود).
- ایراد دسترس‌پذیری ۴: برای رفع، در `06-wp.css` بنویسید `.plan__note a { text-decoration: underline; }`.
- پس از انتقال به دامنه‌ی نهایی: SSL، کش صفحه، فشرده‌سازی، و در Search Console نقشه‌ی `/sitemap.xml` را ثبت کنید.
